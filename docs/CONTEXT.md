# 프로젝트 현재 상태

기준일 2026-11-26. 새 대화에는 이 파일을 먼저 전달하고 작업에 해당하는 기준 문서·코드만 추가한다.

Chozy의 상품·변경 이력, 공급 점수와 홈 추천, 쿠팡 베스트와 네이버 시즌 스냅샷을 PostgreSQL에 저장한다. Spring은 완료 발행본을 읽고 사용자 요청을 처리한다. [처리 구조](ARCHITECTURE.md)와 [프로젝트 배치](../README.md#폴더와-문서)를 참고한다.

| 통합 운영 | ledger·재개·공동 예약·입력 fence·fixture initial→incremental E2E | 실제 운영/Spring 권한·공동 예산/조회/알림·수동 검증 후 자동화 |

2026-11-24 Docker DB에 점수·운영 migration 네 개와 `runtime_budget_guard`, 최소 권한 계획을 적용했다. Spring 전용 로그인으로 예약 함수 실행을 확인했다. 기존 수집기 로그인은 superuser이며 마지막 운영 확인 시 공동 예산 정책은 0건이었다. [DB 권한 분리 검증](VALIDATION.md#db-권한-분리-검증)

쿠팡 베스트 실데이터는 격리 DB에서 발행했고 Spring 홈의 베스트·시즌·비교는 격리 DB로 검증했다. 운영 발행과 Spring 운영 연결은 대기 중이다. [쿠팡 실데이터 검증](VALIDATION.md#쿠팡-베스트-실데이터-검증)

## 다음 작업 순서

1. 오너클랜 묶음 비교는 GraphQL 호출 제한에서 중단했다. 계정의 공동 사용량과 한도·reset을 확인한 뒤 지속 처리와 미반환을 검증한다. 약 5,000개 실제 수집 처리량은 미측정이다. 도매매는 Private 승인과 성공 응답 계약을 확인한다. [오너클랜 실측](VALIDATION.md#오너클랜-api-지연-실측) · [도매매 실측](VALIDATION.md#도매매-private-동기화-재호출)
2. 실제 분포·동시 부하·SLA·보관 기간을 반영해 성능을 검증한다. 일일 고유 변경 약 10만은 계획 가정이다. 점수는 변경·공급사 영향·만료를, 발행은 전체 유효 상품을 처리한다. [1,500만 규모 검증 계획](VALIDATION.md#1500만-규모와-운영-승인-전-남은-조건)
3. 수집기 전용 로그인·DSN을 적용하고 계정별 공동 예산을 등록한다. 수동 수집 재개, 상세 미완료 해소, initial과 새 incremental 작업, Spring 권한·예약·조회·알림을 확인한 뒤 자동화 여부를 결정한다. [운영 전환 절차](RUNBOOK.md#운영-전환-준비와-적용-순서)

최신 테스트와 실측 근거는 [VALIDATION](VALIDATION.md#현재-검증-결과)에 기록한다.
